Walkthrough

Hover a step to find it in the diagram
  1. The app sends a watch event to the sync API.
  2. The sync API publishes it to Kafka, keyed by user ID.
  3. Kafka keeps that user's events in order on one partition.
  4. A writer consumes the events in that order.
  5. It stores them in ScyllaDB, in separate Xstream and IPTV models.
  6. Reads go through a bucket-scoped cache over ScyllaDB.
  7. Watch Info v2 loads continue-watching, history and favourites in parallel.
  8. The client receives one response.
The engineering problem

Several devices, one user, two apps.

Continue-watching and history serve both the Xstream app and the IPTV app at high volume. One user can watch on several devices and write at the same time, so ordering and consistency mattered, and reads had to stay fast.

Decisions and trade-offs

DECISION 1

Serialize writes with Kafka

Events are keyed by user ID, so one user's concurrent and multi-device writes arrive in order. A consumer writes them to ScyllaDB.

Trade-off. Persistence is asynchronous, covered by a local fallback.

DECISION 2

Separate data models per product

Xstream and IPTV have their own continue-watching storage, with table-level compaction tuned for it.

Trade-off. It needs a dual-write migration from the old tables.

DECISION 3

Cache by bucket

Redis and Aerospike caches are scoped per bucket, with bucket-wise diff-sync merge and LRU eviction in the app.

DECISION 4

Reactive reads

Watch Info v2 serves continue-watching, history and favourites through one contract on Spring WebFlux and reactive ScyllaDB, with independent loaders so one slow section does not hold up the others. Later extended to live TV and microdrama.

Failure handling and recovery

A read section is slow

Each section has its own timeout and an empty-page fallback, so the other sections still complete.

Persistence is asynchronous

The write path is backed by a local fallback.

Moving off the old tables

A dual-write migration keeps old and new storage in step while traffic moves over.

Results

Sync latency down by nearly 70%. Watch-history p99 down 75%, with about 4x throughput per instance. The same design now serves live TV, live channels and microdrama.
