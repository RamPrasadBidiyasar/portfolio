01

Context and problem

Every request, the best CDN.

IPTV playback needed each request sent to the best CDN as geography, load and CDN health change, and needed to keep playing when a CDN degrades.

02

System architecture

Conceptual, not the production topology

Hover or tap a step in the flow below to find it in the diagram

03

Request and event flow

Orange steps run only on failure
  1. A playback request arrives with its context: geography, user and channel.
  2. The engine reads the routing rules from the MongoDB-backed store.
  3. A filter engine removes ineligible CDNs.
  4. A sort engine orders the rest, and a rule-evaluation engine applies priorities and weights.
  5. The selected CDN serves the stream.
  6. If no rule matches or selection fails, the request falls back to stream options ordered by default weight.
04

Technical implementation

RoleEngineered the routing and failover
TeamXstream backend, Airtel Digital
ServesIPTV playback
StackJava · Spring Boot · MongoDB · SpEL rules
  • 01Rules as configuration. Routing rules are stored in MongoDB and evaluated per request over geography, user, channel, priority, weights and CDN health.
  • 02Filter, then sort. A filter engine removes ineligible CDNs, a sort engine orders the rest, and a rule-evaluation engine applies priorities. Rule storage, access and sync mechanisms keep the rules available to the playback service.
  • 03Always have an answer. If no rule matches or selection fails, the request falls back to stream options ordered by default weight. A priority-CDN override gives operators manual control, and fallback decisions are recorded.
05

Decisions and trade-offs

Decision 01

Rules as configuration

Trade-off. A rule engine needs its own testing and change history.

06

Failure handling and reliability

If

No rule matches

The request falls back to stream options ordered by default weight.

If

Selection fails

The same default-weight order is used, so playback still gets a CDN.

If

Operators need control

A priority-CDN override lets them force a CDN, and each fallback decision is recorded.
